# Dashboard

使用 Dashboard 将 MQTT 消息字段展示为数值、仪表盘和趋势图。按本文先连接并接收数据，再配置组件，最后核对实时更新与本地历史记录。

直接在 **视图器 → 仪表盘** 中配置，无需使用 MQTTX Agent。为每个组件选择连接、主题过滤器与 Payload 字段，即可将不同数据源的指标安排在同一视图中。

![MQTTX Dashboard](https://mqttx.app/images/mqttx-dashboard.png)

## 连接并接收数据

1. 将 MQTTX 客户端连接到接收设备消息的 Broker。
2. 订阅设备主题或 MQTT 主题过滤器，例如 `factory/+/telemetry`。
3. 在连接的消息列表中确认消息已到达。

Dashboard 使用 MQTTX 接收到的消息。在组件中选择主题过滤器，不会替客户端创建该主题的订阅。

在已收到的 Payload 中确定需要展示的数值字段。例如：

```json
{
  "deviceId": "line-01",
  "temperature": 24.8,
  "humidity": 56,
  "pressure": 1.02
}
```

将组件的**字段**设置为 `temperature`、`humidity` 或 `pressure`，以读取对应数值。

## 为每个指标选择合适的展示方式

- **Big Number**：突出当前读数，适合温度、压力或设备发送的计数值。
- **Gauge**：将读数放在一个范围内，适合展示 0–100% 的湿度等指标。
- **Line**：展示数值随时间的变化，便于检查趋势或测试过程中的波动。

对于准备步骤中的 JSON 示例，分别添加温度 Big Number、湿度 Gauge 和压力 Big Number，再添加一张温度 Line 曲线，检查随时间的变化。

## 创建 Dashboard

1. 从左侧栏进入 **视图器 → 仪表盘**。
2. 点击**新建仪表盘**，填写名称和描述。
3. 点击**添加组件**，选择 **Big Number**、**Line** 或 **Gauge**。
4. 配置数据源，以及该组件类型提供的选项。
5. 拖动和缩放组件，安排展示位置，再按需添加其他指标。

拖动仪表盘列表的右边缘可以调整列表宽度。右键点击某个仪表盘，或使用它的 `⋯` 菜单，可以编辑或删除。

### 将组件绑定到消息字段

在**数据源**中配置：

| 字段     | 选择内容                       |
| -------- | ------------------------------ |
| 连接     | 正在接收消息的 MQTTX 连接      |
| 主题模式 | 要匹配的主题或 MQTT 主题过滤器 |
| 字段     | Payload 中所需数值的 JSON 路径 |
| 回退值   | 无法读取指定字段时使用的数值   |

实时匹配与历史查询都支持 MQTT `+`、`#` 主题过滤器。精确主题用于选择单台设备的读数，主题过滤器用于匹配多个主题。一个共享过滤器不会自动为每台设备创建独立的曲线。

### 让读数更容易理解

按指标为组件命名。根据所选类型配置颜色、小数位数、单位、范围、阈值或线条样式等可用选项。线条展示支持时，编辑器会提供**平滑线条**和**区域填充**选项。

以上例为例，为温度和压力数值组件设置 °C、bar 单位，将湿度仪表盘范围设为 0–100%。折线图可以命名为 **Temperature trend (°C)**，直接说明展示的指标和单位。

不同组件提供的配置项有所区别。图表颜色会跟随 Light、Dark 和 Night 主题。

## 跟随新消息更新，并查看历史变化

1. 通过设备或另一个 MQTT 客户端，向组件过滤器匹配的主题发布消息，在选定连接的消息列表中确认消息已到达。
2. 将组件读数与指定 Payload 字段对照。如果显示回退值，检查 JSON 路径和字段数值。
3. 再发布一条数值不同的消息，确认数值或 Gauge 读数更新，或 Line 曲线新增数据点。未更新时，检查连接是否有效、Broker 订阅、主题过滤器与组件选择的连接。
4. 在工具栏选择覆盖已收到消息的时间范围，将展示的历史与本地保存的消息记录对照。

历史查询使用本地消息记录，不会向 Broker 补取 MQTTX 此前没有收到的消息。观察持续的实时更新时，保持消息源继续发布。

<details>
<summary>布局与历史数据限制</summary>

- 仪表盘列表宽度可设置为 160 至 400 像素，MQTTX 会记住该宽度。
- 组件使用 12 列网格。
- 每个组件最多展示所选时间范围内最新的 1,000 个数据点。

</details>

## 示例：让 MQTTX Agent 准备一个数据视图

1. 按 [MQTTX Agent 指南](https://mqttx.app/zh/docs/agent) 完成配置并打开 Agent，输入 `/`，选择 Zero EMQX Skill。
2. 提交以下请求，创建临时 Broker、发布样本消息并准备 Dashboard：

> 创建一个 Zero EMQX 临时 Broker，将连接保存为 Factory Demo 并连接，订阅 `factory/+/telemetry`。向 `factory/line-01/telemetry` 逐条发送 12 条包含 `deviceId`、`temperature`、`humidity`、`pressure` 且数值有变化的 JSON 消息，再创建名为 Factory Overview 的 Dashboard：显示温度、湿度和压力读数，并放一张温度趋势图，最后打开面板。

3. 在操作前询问模式中检查并批准操作，确认 Factory Demo 已连接、订阅存在，并在 `factory/line-01/telemetry` 收到逐条发送的 JSON 消息。
4. 打开 Factory Overview，将当前读数与最新消息对照，再选择覆盖样本消息的历史时间范围检查趋势。

后续按上文的手动控件继续编辑 Dashboard。更换 Broker 或数据源时，先连接并订阅，再修改组件的数据源设置。
